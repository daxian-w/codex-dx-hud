## 1. 文档用途与阅读规则

本规范交付开发人员和验收人员使用。目标是在保留原有悬浮条与窗口吸附功能的基础上，新增参考图中的紧凑悬浮球、悬停展开卡片，并统一程序自有的托盘菜单、设置窗口视觉。

本文使用三类标记：

- **已确认**：用户明确同意的需求，构成本次交付范围。
- **工程默认**：为使开发可执行而补充的参数或规则，可根据原型和测试微调；不表示用户已经逐项确认。
- **待验证能力**：必须通过本机协议和真实客户端实验确认，不能用文档中的设想代替实现证据。

所有验收项状态初始为“未执行”。已有 0.3.2 构建或回归结果只能作为基线，不能作为改造后的通过记录。

6. 明确完成标准：错误兜底通过不等于真实任务监控功能已经通过。

## 3. 范围、默认行为与兼容原则

### 3.1 三种用户可选模式

| 设置中的选项 | 内部窗口行为 | 外观 | 鼠标行为 |
|---|---|---|---|
| 桌面悬浮条 | desktop | strip | 保持现有拖拽行为 |
| 窗口吸附条 | attach | strip | 保持点击穿透及原有吸附位置 |
| 玻璃悬浮球 | desktop | orb | 悬停展开、可拖拽、可打开菜单 |

**工程默认**：使用现有 `OverlayMode` 表达 desktop/attach，新增 `DesktopWidgetStyle` 表达 strip/orb。不要直接使用原稿的 `OverlayMode: orb`，因为现有窗口显隐、顶置和鼠标处理以 desktop/attach 为条件。

悬浮球仅用于桌面模式。窗口吸附继续穿透，不同时承诺“穿透底层”与“捕获悬停展开”。切回桌面时可恢复此前选择的样式。悬浮球和旧条分别保存位置，避免展开后的坐标覆盖旧条位置。

### 3.2 安装与升级默认

- 已确认的默认值是悬浮球尺寸“紧凑”，与是否默认启用悬浮球是两个概念。
- **工程默认**：升级时保持原有模式、位置、语言、启动设置、字号和配色；新增尺寸设为 compact。新装仍沿用现有桌面条默认，用户选择玻璃悬浮球后启用。
- 若后续希望新装默认启用悬浮球，可调整出厂配置；不得因此强制切换旧用户的模式。
- 停用悬浮球时保留其尺寸、位置和外观偏好，便于再次启用。

### 3.3 本次边界

本次负责监视器自有界面及只读数据展示。额度计算、登录流程、重置券核销、Codex 本体修改、云端账号系统不在范围内。

“托盘统一视觉”指应用图标、应用自有右键菜单及提示信息组织。Windows 任务栏、系统托盘宿主、系统原生气泡和窗口标题栏仍由系统控制；不得将修改这些系统界面作为验收条件。

## 4. 数据真实性与接入可行性

### 4.1 已核对的项目事实

当前源码通过本程序启动的 app-server 读取账号及额度；初始化时排除了部分线程通知。项目刷新说明也明确：这些通知来自监视器自己的连接，而非官方客户端的请求或推送。[本地源码](../src/CodexRateMonitor.cs)、[刷新说明](../docs/usage-refresh.md)

因此，移除通知排除列表只能允许该连接接收通知，不能据此证明可以观察用户正在使用的 Codex 桌面端。读取历史会话也不能单独证明当前仍在执行。

### 4.2 官方协议依据及限制

官方协议文档描述了线程状态通知、轮次开始/结束及计划更新事件；计划条目有待执行、进行中和完成状态。`thread/read` 是只读历史读取，不等同于订阅；`thread/loaded/list` 描述服务端内存中的会话。协议 schema 可以由对应 CLI 版本生成。以上说明不构成“独立监视器可观测桌面端全部实时任务”的保证。[OpenAI App Server 文档](https://learn.chatgpt.com/docs/app-server)

本项目应将相关事件视为候选输入，字段、作用范围和版本兼容性以目标电脑验证结果为准。该结论属于本项目的工程判断。

### 4.3 M0 接入验证：必须先得到证据

正式任务数据接入前，输出一份脱敏的 `capability-report.md`，至少记录：

1. 实际使用的 Codex 可执行文件、CLI 版本、桌面端版本、协议 schema 版本。
2. 监视器连接的是自身进程还是已验证的桌面端只读数据源。
3. 在桌面端真实任务启动、等待、完成、中断时，监视器能看到哪些字段和变化。
4. 是否能得到稳定会话/轮次标识、计划步骤列表；跨进程和跨账号的范围是否清楚。
5. 分页是否完整、归档会话是否排除、子代理是否会重复计数、重启后如何恢复。
6. 能力结论：实时状态可用、计划进度可用、只可读历史、部分可用或不可用；每项附证据。

候选方法先查目标版本 schema，再做只读探测。不得为了获取通知而恢复、启动、打断真实会话，也不得通过发送新提示词来制造“被监控任务”。

如果当前连接无法读取桌面端状态，记录具体原因并显示“任务状态不可用”。继续完成视觉与错误兜底；真实任务监控的验收状态仍为“阻塞”。接入新数据源若涉及新的权限或修改桌面端运行方式，需要单独记录方案及影响。

### 4.4 三类数据彼此独立

| 数据域 | 真值来源 | 错误处理 | 不能作出的推断 |
|---|---|---|---|
| 额度 | 现有账号确认与额度读取链路 | 可保留同账号缓存，并注明更新时间/失败 | 不能从 token 数估算订阅剩余额度 |
| 任务 | M0 证明可观察目标会话的数据源 | 显示不可用、部分范围或过期 | 没收到通知不代表没有任务 |
| 重置券 | 现有只读查询链路 | 显示未知/缓存/失败 | 查询失败不代表券数为 0 |

账号范围无法与桌面端核对时，额度提示应写明“本地登录账号”；不要声称必然与当前桌面端账号、工作区相同。任务也应显示已验证的观测范围。

### 4.5 “2/5”及任务统计口径

**工程默认**：参考图顶部的 2/5 定义为“选中会话当前轮次的计划已完成步骤数 / 最新计划总步骤数”。只有拿到该轮次的结构化计划时才显示，例如“进行中 · 步骤 2/5”。

- 5 小时额度环中心显示额度百分比，不复用任务步骤数。紧凑图中原来的 2/5 被用户已确认的 5 小时额度环需求替代。
- 已完成条目数作为分子，最新完整计划条目数作为分母。收到计划修订时整体替换；比例可以随计划扩充而下降。
- 没有计划时显示真实状态及“未提供步骤”，不能把工具调用次数、已生成文字、token 数或耗时作为进度。
- 分母为 0 时不做除法，显示“未提供步骤”；任务已完成并不强制将没有更新完的计划补成 100%。
- **工程默认**：多会话时展示“进行中 N 项”等可核实汇总；单独的步骤进度仅用于一条可明确关联的会话。优先展示等待用户处理的会话，其次最近更新的活跃会话。若切换，显示会话短标题并重置步骤上下文。
- 如果只能观察部分会话，文案加“已观测”，不能把局部统计写成整台电脑的全量任务数。子代理不额外叠加为顶层任务，除非后续明确启用不同统计口径。
- 总数未知时不显示 N/M；可以显示可信的活动数及“范围不完整”。没有任务能力时也不得显示“0 项”冒充空闲。

### 4.6 状态与文案

| 数据情形 | 简体中文示例 | 计数/进度处理 |
|---|---|---|
| 首次读取 | 正在读取任务状态… | `—`，不显示成功 |
| 确认覆盖范围内没有活动任务 | 空闲 · 0 项进行中 | 真实 0 |
| 正在执行、有结构化计划 | 进行中 · 步骤 2/5 | 使用当前轮次最新计划 |
| 正在执行、没有计划 | 进行中 · 未提供步骤 | 不展示数值进度条 |
| 等待审批或输入 | 等待确认 / 等待输入 | 保留有依据的步骤数，不自行推进 |
| 任务完成/失败/中断 | 已完成 / 任务失败 / 已中断 | 与通信失败分别展示 |
| 接口不支持或未连接到目标会话 | 任务状态不可用 | `—`，提供原因提示 |
| 读取超时 | 任务读取失败 | 可显示历史记录，但明确“缓存” |
| 观测范围有限 | 已观测 2 项进行中 | 不宣称完整覆盖 |
| 会话未加载、退出或状态过期 | 状态未知 / 数据已过期 | 不自动归为成功或空闲 |

选择“明确错误”作为用户允许的“错误或 0”兜底方式。异常时使用 `—`，零仅表示已被数据证明的零。

等待状态优先于正在执行的普通状态；失败终态不可被旧的进行中事件覆盖。**工程默认**：最近终态保留 5 秒用于提示，之后依据新的完整快照决定是否回到空闲，而非仅凭时间清零。

### 4.7 额度、重置时间与重置券

- 沿用 `UsageDisplay` 的 remaining/used 口径；环与条显示同一种口径，提示文字标明“剩余”或“已用”。
- 显示值遵循现有格式函数；绘制比例限制在 0%–100%，异常非数值按未知处理。
- 缺少某个额度窗口显示“未提供”，保留另一窗口真实值；不能复制或补算另一项。
- 紧凑球固定保留 5h 环和 7d 条，缺失者显示占位。旧 `UsagePanels` 筛选继续用于原悬浮条；设置中标注它不改变悬浮球固定结构。
- 额度重置以服务端确认值为准，不在本地倒计时结束时自行设为 100%。
- 重置时间按当前系统时区显示，完整时间和上次确认时间放入提示信息；跨时区不改变原始时间戳。
- 券只读展示，不提供核销按钮。存在可用券时显示数量和最早到期日；7 天内用警告色，3 天内用危险色。
- **工程默认**：开启券展示时，成功确认零券显示“券 ×0 / 暂无可用券”；未知显示“券 — / 读取失败”，有缓存需注明。关闭券展示则移除该卡片，两个额度卡片均分下排空间。
- 该零券规则仅用于新悬浮球，旧条保持原有零券隐藏行为。

## 5. 紧凑与展开界面规格

### 5.1 紧凑悬浮球

采用横向圆角小卡片，而非几何正圆。上区左侧品牌图标和连接状态点，中央轻分隔线，右侧额度环；下区为 7 天进度条和百分比。

5h 环保留“5h”小标识，避免将百分比误读成任务进度。状态点只代表数据连接健康，不代表任务正在执行：

- 绿色：额度连接最近成功，数据未过期。
- 琥珀色：连接中、缓存或暂时失败。
- 红色：登录失效或持续通信错误。
- 灰色：尚无有效连接数据。

任务数据源不可用时，在展开顶部单独说明；不得因为额度成功就宣称任务监控正常。状态不能只依靠颜色区分，提示文字必须说明。

### 5.2 展开卡片

顶部是任务摘要卡，包含进度环/状态符号、任务文案和辅助进度条。下排是蓝色 5h 额度卡、紫色 7d 额度卡、橙色重置券卡。

- 顶部两个进度元素必须绑定同一份真实计划进度；没有数值进度时呈中性状态，不保留参考图中的固定 40%。
- 参考图右上黄色胶囊按进度指示处理，不作为未定义的开关。
- 额度卡优先显示百分比，重置时间用较小文字或提示显示；过期状态直接可见。
- 长会话标题可省略，完整标题放在提示中；状态、百分比和错误提示不可被标题挤出。
- **工程默认**：任务显示可关闭，关闭后不显示任务卡，底部卡片上移，窗口自然缩短，宽度保持不变。
- 所有正常数据示例只允许出现在标有“示例数据”的设置预览和测试程序中。

## 6. 交互、展开方向与位置

### 6.1 状态转换

| 当前状态 | 事件 | 下一状态/行为 |
|---|---|---|
| 折叠 | 鼠标进入有效卡片区域 | 等待展开 |
| 等待展开 | 持续停留达到延迟 | 展开中 |
| 等待展开 | 鼠标提前离开 | 取消计时，仍折叠 |
| 展开中 | 动画结束 | 已展开 |
| 已展开 | 鼠标离开、无拖拽/菜单/设置交互 | 等待收起 |
| 等待收起 | 鼠标返回 | 取消收起，保持展开 |
| 等待收起 | 达到延迟 | 收起中，完成后折叠 |
| 任意可见状态 | 左键拖动超过系统拖拽阈值 | 拖拽中，暂停展开/收起计时 |
| 拖拽中 | 松开左键 | 保存折叠锚点，按当前指针位置恢复悬停判断 |
| 任意可见状态 | 打开本程序菜单/设置 | 暂停自动收起或维持明确预览状态 |
| 任意状态 | 同屏全屏触发隐藏 | 停止动画/计时，隐藏；恢复时先折叠 |

**工程默认**：移入延迟 120ms，移出延迟 260ms，展开/收起动画 180ms；延迟分别可调，动画可关闭。使用单调时钟，系统时间调整不改变交互计时。

鼠标从小卡片移动到展开后的内部区域必须连续保持展开。透明阴影区域不作为卡片有效命中范围。数据更新时不得重建一个会触发假移出的窗口。

### 6.2 点击和菜单

当前桌面条主要是拖拽；托盘双击用于打开设置。新增悬浮球行为按以下工程默认实施：

- 左键单击：不执行任务控制或券核销；悬停关闭时，单击切换展开/折叠。
- 左键拖拽：使用系统拖拽阈值区分点击；拖动中的单击/双击动作取消。
- 左键双击：打开现有设置窗口，定位到悬浮球设置区。
- 右键：打开与托盘一致的应用菜单；右键不得触发拖拽。
- 鼠标悬停展开不得抢焦点。打开设置是明确点击操作，可以激活设置窗口。
- 托盘双击、右键菜单和退出路径继续可用。

### 6.3 展开几何与多屏

- 持久化的是折叠卡片的锚点，而非展开窗口左上角。
- 按折叠卡片中心所在显示器决定工作区，左半区向右、右半区向左展开；空间不足时选择可容纳的方向。
- 靠近底部时向上展开，顶部空间优先向下。展开卡片应覆盖原折叠区域，使指针仍落在有效区域内。
- 最终将可见卡片约束在该显示器工作区内；**工程默认**安全边距 8 DIP。旧条允许覆盖任务栏的原行为保持。
- 收起后回到原折叠锚点，不因多次展开发生位置漂移。
- 展开期间拖动时，以位移同步更新折叠锚点；结束后保存该锚点。
- 支持副屏负坐标、不同 DPI、竖屏、主屏切换和显示器移除；移除时将卡片迁到最近可用显示器。
- 所选档位在小屏无法完整容纳时，按工作区等比缩小，设置提示“已适配屏幕”；不修改用户保存档位。
- 在同一显示器从折叠到展开期间固定方向；拖动结束后可重新选择方向，避免中途跳边。

### 7.4 动画与低占用

尺寸/位置与内容透明度协同过渡，建议 ease-out。动画仅在交互过渡时运行，静止时停止动画定时器；不持续旋转、呼吸或闪烁状态灯。

“玻璃质感强度”对应高光和柔光参数，界面不称为真实“桌面模糊强度”。阴影由缓存位图或绘制资源复用；不循环截屏。

## 8. 设置、托盘及多语言

### 8.1 现有设置窗口的信息组织

建议保留窗口入口和保存/取消语义，将内容组织为：

1. 外观预览：折叠/展开预览切换，标注示例数据。
2. 显示方式：三种模式，原有位置与行数仅在适用模式显示。
3. 悬浮球：七档尺寸、悬停展开、移入/移出延迟、动画、任务区开关。
4. 玻璃外观：透明度、圆角系数、柔光强度，恢复默认。
5. 数据显示：剩余/已用、显示重置券；旧条面板选项标注适用范围。
6. 通用设置：语言与现有字体/颜色参数；原条专用参数不误导成控制悬浮球。
7. 固定页脚：保存并关闭、取消，内容较长可滚动而页脚可达。

保存失败必须提示，不能表面关闭窗口而丢失设置。恢复默认只修改当前编辑副本，取消后应恢复原状。

### 9.1 建议配置结构

### 9.3 迁移与持久化

1. 读取旧版配置，保留原位置、缩放、透明度、语言、刷新周期及自定义颜色。
2. 新字段缺失时补默认，不将旧条自动变成球；原 `ScaleBasisVersion` 迁移逻辑继续有效。
3. 设置预览通过深拷贝，新增 Orb 对象与 Position 对象不能共享可变引用。
4. 保存使用同目录临时文件与替换策略，并保存可恢复的前一份配置；首次文件不存在时使用创建路径。
5. 配置损坏时给出提示，保留损坏原件；不要直接覆盖为默认而丢失用户数据。
6. 写权限失败时提示并保留编辑状态；退出时避免重试循环和 UI 阻塞。
7. 升级迁移在独立备份上测试；回滚时恢复旧可执行文件及对应的升级前配置。

### 10.2 建议数据契约

| 字段 | 类型/允许值 | 用途 |

| ThreadId / TurnId | 可空标识 | 将状态和计划绑定同一会话与轮次 |

### 10.3 刷新、缓存与事件规则

- 额度沿用现有前台30秒、后台60秒、最小化/隐藏300秒默认节奏，重置券默认30分钟。悬停不额外触发一轮账号或券网络请求。[项目刷新规则](../docs/usage-refresh.md)
- 任务状态优先使用M0证明有效的事件流；只在来源支持时增加合并后的只读校验。
- **工程默认**：如果必须轮询有效任务数据源，展开期间最多每5秒一次，折叠15秒一次；请求未完成不并发，单次超时10秒，失败按15/30/60秒退避。若数据源不适合这个频率，在M0报告中调整并记录实测原因。
- 任务确认过期阈值默认 `max(30秒, 2×当前校验间隔+10秒)`。可确认的连接保活不等于任务状态已经重新核实；只有有效快照或有保证的持续订阅才可维持可信状态。
- 无保活、无校验、无事件可靠性保证的来源应进入“状态未知/过期”，不能永久显示“进行中”。
- 失败时保留同账号最后成功值并加缓存标记；明确登录失效、账号变化时清除旧额度、券与任务上下文。
- 迟到响应按请求/账号/连接版本过滤；新轮次开始后丢弃上轮计划事件。
- 重复事件不得重复计数；不能仅靠本地到达顺序解决真正的乱序。没有上游版本号时，通过完整快照校验消除不确定性。
- 休眠唤醒后重新确认连接和快照；动画与悬停计时重置，不把休眠期间推断为完成。
- 应用退出后释放图形资源、定时器、订阅和自身子进程；不得结束用户的 Codex 桌面进程或其任务。

### 10.4 实现限制

任务状态解析不读取消息正文来猜测进度，不依靠屏幕OCR推断“生成中”，不以历史文件数量或没有事件推断全局任务数。确需只读本地状态作为替代来源时，应先确认格式、更新时延、范围和过期语义，并记录在能力报告中。

日志仅记录固定状态、耗时、事件类型与脱敏错误码，不记录访问令牌、原始账号信息、会话正文或完整协议响应。保持现有诊断默认关闭。设置预览数据与生产数据路径隔离，发布程序不得自动启用演示状态。

## 11. 性能与稳定性目标

以下为**建议验收预算，尚未实测**。先测0.3.2基线，再在同一机器、同一缩放、相同账号状态下测新版。记录CPU型号、核心数、内存、Windows版本、显示器DPI和测量工具。

| 项目 | 测量方式 | 工程验收目标 |
|---|---|---|
| 静止折叠CPU | 预热2分钟后采样5分钟，按整机总CPU容量归一化 | 监视器平均≤0.5%，较基线增量≤0.3个百分点 |
| 静止展开CPU | 同上，数据不频繁变化 | 监视器平均≤1.0% |
| 内存增量 | 相同条件下Private Bytes稳定值比较 | 监视器较基线增加≤40MiB |
| 重复交互资源 | 200次开合、50次设置打开/关闭，静置2分钟后对比 | 无持续上升；Private Bytes增量≤10MiB，GDI句柄净增≤20 |
| 单帧绘制 | 开合过程中记录绘制耗时 | p95≤33ms，无可感知长停顿 |
| 悬停响应 | 记录进入到开始动画 | 不超过设置延迟+100ms |
| 收起响应 | 记录离开到开始动画 | 不超过设置延迟+150ms |
| UI处理任务事件 | 有效事件抵达解析器到可见更新 | p95≤500ms；不包含上游不可控延迟 |
| 展开触发网络 | 对比连续200次开合前后请求计数 | 不因开合增加额度/券请求 |
| 空闲绘制 | 无数据变化时统计重绘 | 无持续动画/截图循环，只允许必要状态变更重绘 |
| 退出 | 菜单退出后观察5秒 | 自身窗口/定时器/所拥有子进程退出 |

app-server的CPU、内存、网络开销单独记录，并同时报告监视器与其子进程的合计值；不得只展示小型UI进程的指标就宣称总开销降低。原有50ms顶置行为需与基线分开评估；本次不得再增加高频全桌面轮询。

若目标机持续超出预算，应减少动画、缓存阴影或降低非必要轮询后复测。不能在没有测量的情况下写“低占用验收通过”。

## 14. 视觉验收方法与证据

### 14.1 比较方式

- 以参考图左、右两张卡片分别作为折叠、展开的视觉对照；去掉周围自然背景、箭头和注释后按比例比较。
- 固定DPI、尺寸档位、语言、桌面背景和输入状态。测试渲染可使用5h100%、7d84%、券3张及步骤2/5，但在文件名或画面中标“示例数据”。
- 额外提供真实运行截图，数值不必与参考图相同，必须能追溯到同期来源。
- 正常场景对比卡片位置、图标比例、字号、圆角、描边、阴影和渐变；异常场景对比错误提示是否仍清晰。
- 参考图属于视觉示意，不要求位图逐像素相等；文字清晰、数据真实和系统兼容优先于仿造不可读的小字。

### 14.2 可量化检查

1. 窗口物理尺寸与公式误差≤1像素；布局关键坐标与本规范工程基线误差≤2 DIP。设计微调后先更新基线再测。
2. 主数据、状态文本、保存/取消按钮不得裁切；长标题允许省略并可查看完整提示。
3. 所有透明边角无黑边、色块和矩形残影，深浅背景均检查。
4. 七档使用同一结构；任务/券关闭后的布局符合第7节。
5. 同一状态静置时不持续重排；连续展开200次后锚点无累计漂移。
6. 券到期、任务失败、通信错误不依赖单一颜色，提示仍可辨识。

### 14.3 必须交付的截图/记录

- compact-collapsed、compact-expanded：紧凑档两种形态。
- sizes-overview：七档对照，注明DPI。
- edge-placement：四角方向与收起后锚点。
- settings-zh-CN、settings-zh-TW、settings-en：设置窗口及新增区。
- tray-menu、update-dialog：应用自有菜单和更新内容区。
- data-errors：任务不可用、额度缓存、券未知等状态。
- live-task：真实任务状态至少一次起止或等待过程，附来源时间。
- dpi-mixed：跨DPI和副屏场景。
- interaction：短录屏或逐帧证据，覆盖移入、移出、拖拽、快速返回。

报告记录问题编号、严重度、截图、修复版本及复测结果。截图数量不足、只查看进程存在、只通过构建，都不能替代GUI验收。
